## 一句话

**行业里所有人都在声称"准确率 95%"，但没有任何一把尺子能验证它。PV-IRBench 就是那把尺子。**

我们不训练最强的检测模型。我们做的是：**定义一套能回答"这个模型能不能上工"的指标，
并把它开源出来，让任何人的声明都可以被复算。**

## 为什么需要它

### 问题一：mAP 不是运维要的指标

mAP 是为通用目标检测设计的学术指标，它衡量的东西和运维关心的事情几乎不重合：

- **它对负样本不敏感** —— 一个在正常组件上疯狂误报的模型，mAP 依然可以很高。
  而误报意味着派人白跑一趟，这是运维成本的主体。
- **它平等对待所有类别** —— 漏检一个可能引发火灾的组串开路故障，
  和漏检一个轻微热斑，在 mAP 里损失相同。
- **它不反映定位是否可用** —— 框错到隔壁组件，IoU 仍可能达标，但报告作废。

详见 [`docs/metrics.md`](docs/metrics.md)：六个运维可用性指标（FAR / wMR / LA / ΔT-MAE / CS / LSR）。

### 问题二：各家的数字根本不可比

我们在跨数据集评测中实测到：同一个模型，在同域数据上图像级召回 **97.44%**，
在另一个公开数据集上只有 **0.10%** —— 相差近千倍。

根因不是模型不行，而是**评测条件从未对齐**：

| | 自有验证集 | InfraredSolarModules（Raptor Maps） |
|---|---|---|
| 图像尺寸 | 640×640 | **40×24** |
| 标注粒度 | 框级 | 图像级 |
| 类别体系 | 4 类 | 11 类异常 |
| 成像模态 | 红外热成像 | 红外热成像（单组件裁剪） |

**尺度相差 16–26 倍。** 在这种情况下，任何"我们比他们高 5 个百分点"的说法都没有意义。

这不是一个失败的实验——**它是本基准存在理由的实证。**

### 问题三：没人能测量假警报率

多数公开数据集与竞赛榜单**不含足量纯负样本**，因此 FAR 根本无法测量。
这就是为什么"95% 准确率"永远无法被验证。

PV-IRBench 验证集的负样本占比为 **30%（151/503）**。

## 首个基线结果（v0.1）

权重 `runs/final/best.pt`，自有验证集 503 张（含正常组件 151 张）。

**FAR–召回权衡曲线：**

| conf | FAR 假警报率 | 每千块误报框 | 图像级召回 | StringFault 召回 |
|---|---|---|---|---|
| 0.25 | 0.00% | 0.0 | 93.47% | 56.2% |
| **0.10（推荐工作点）** | **0.00%** | **0.0** | **97.44%** | **84.4%** |
| 0.05 | 0.66% | 6.6 | 97.73% | 84.4% |
| 0.01 | 2.65% | 33.1 | 98.86% | 90.6% |

**这张表本身就是论点。** 单看一个 mAP 数值，永远发现不了：
把阈值从 0.25 降到 0.10，最弱类别召回提升 **28.2 个百分点**，而假警报率代价为零。

### 另一个发现：框级指标严重低估可用性

StringFault 的 mAP50-95 只有 0.407，看似很差；但在 conf=0.10 下图像级召回达 **84.4%**。

含义：**模型"知道这块板有问题"的能力，远强于"精确指出问题在哪"的能力。**
而运维筛查阶段只需要前者。这说明以 mAP 为唯一验收标准会系统性低估模型价值。

## 快速开始

评测脚本与训练框架解耦：只要你的模型能对一批图片输出检测结果，
就可以计算 FAR 与图像级召回。

```bash
# 自有数据集（需要有 label 目录，空 label 文件即为负样本）
python benchmark/eval_far.py --source own --data <数据集根目录> --conf 0.10

# 扫描多个阈值，生成 FAR–召回权衡曲线
python benchmark/eval_far.py --source own --data <数据集根目录> --sweep
```

输出为 JSON，含 FAR、每千块误报框、图像级召回与逐类别召回。

## 边界声明（重要）

为避免本基准被误用，明确声明 v0.1 的能力边界：

- **同域结果不等于真实电站表现。** 当前基线来自自有验证集，非现场部署数据。
- **图像级指标不代表定位精度。** 当前仅评估"该图是否检出缺陷"，不评估框的位置。
- **不主张跨数据集的横向对比。** 各数据集的模态、尺度、标注粒度差异过大，
  本协议暂不提供跨数据集的绝对比较方法（见 `docs/protocol.md` 第六节）。
- **不提供检测报告。** 本项目不具备 CMA/CNAS 资质，产出的是**算法评测结果**，
  不是具有法律效力的检测报告。
