# PV-IRBench 运维可用性指标体系

> 作者／维护：光驭智检 PV-Inspect AI · 版本 v0.1（2026-11-01）
> 许可：本文档采用 CC BY 4.0

## 为什么需要这套指标

光伏 AI 巡检领域普遍使用 mAP 报告性能，但 mAP 是为通用目标检测设计的学术指标，
**它衡量的东西和运维真正关心的事情几乎不重合**。

三个根本性的错配：

1. **mAP 对负样本不敏感。** 运维的成本大头是"派了人去现场，发现没事"——
   即假警报。一个在纯正常组件图上疯狂误报的模型，mAP 依然可以很高。
2. **mAP 平等对待所有类别。** 漏检一个组串开路故障（可能引发火灾）
   和漏检一个轻微热斑，在 mAP 里是一样的损失。运维视角下完全不是。
3. **mAP 不反映定位是否可用。** 框只要 IoU 达标就算对，但运维拿到框是要去
   找那块板的——框错了等于白检。

**结论：mAP 不是错的，但它不足以回答"这个模型能不能上工"。**

## 六个指标

### 1. FAR · 假警报率（False Alarm Rate）

**定义**：在所有确认为正常的巡检单元上，被模型判定为存在缺陷的比例。

```
FAR = FP / (FP + TN)
```

配套绝对量：**每千块误报框数** `= 误报框总数 / 正常单元数 × 1000`

**为什么 mAP 替代不了**：mAP 的精度项会被大量易检出的真阳性稀释，
对"在干净场景下乱报"几乎不设防。而 FAR 直接决定派单成本——
一家管 500 个电站的运维商，FAR 每高 1 个百分点，一年就是数百次冤枉出勤。

**当前基线（PV-IRBench v0.1，自有验证集 151 张正常图，conf=0.10）**：
`FAR = 0.00%`，每千块误报框 0.0

---

### 2. wMR · 严重度加权漏检率（Weighted Miss Rate）

**定义**：按缺陷严重度加权后的漏检比例。

```
wMR = Σ(漏检数_i × 权重_i) / Σ(总数_i × 权重_i)
```

建议权重（基于 IEC TS 62446-3 的 ΔT 分级与失效后果）：

| 类别 | 建议权重 | 依据 |
|---|---|---|
| 组串开路 / 反极性（StringFault） | **5** | 可导致整串失效、直流拉弧与火灾风险 |
| 二极管失效（Diode） | 3 | 持续发热，加速组件衰减 |
| 热斑（HotSpot） | 3 | 局部高温，可致组件永久损伤 |
| 旁路（ByPassed） | 2 | 功率损失，一般不会立即恶化 |

**为什么 mAP 替代不了**：mAP 对每个类别等权，而运维的风险是重尾分布的。
一个漏掉所有组串故障但热斑全中的模型，mAP 可能不错，实际却是灾难。

---

### 3. LA · 定位准确率（Localization Accuracy）

**定义**：检出框的中心点落在正确组件范围内的比例。

```
LA = 中心点落位正确的检出数 / 检出总数
```

**为什么 mAP 替代不了**：IoU ≥ 0.5 即可算真阳性，但在航拍图上，
相邻组件的 IoU 很容易达标而组件编号错了。运维拿到报告要按编号去找板，
定位错等于这张报告作废。

---

### 4. ΔT-MAE · 温差回归误差

**定义**：模型估计的缺陷相对温差 ΔT 与辐射测温实测值的平均绝对误差（单位 K）。

```
ΔT-MAE = mean(|ΔT_pred − ΔT_measured|)
```

**为什么 mAP 替代不了**：IEC TS 62446-3 的异常分级
（<2K 噪声 / 2–10K 轻微 / >10K 严重）**完全建立在 ΔT 之上**。
不能给出可信 ΔT，就无法出具符合标准的报告，也就无法用于质保索赔。
检测框告诉你"这里有异常"，ΔT 才告诉你"有多严重、要不要现在处理"。

⚠️ 当前项目状态：**尚未实现**（无辐射定标，不能声称℃）。这是 v0.2 的首要目标。

---

### 5. CS · 跨条件稳定性（Cross-condition Stability）

**定义**：各评测切片上指标的标准差。

```
CS = std(指标_切片1, 指标_切片2, ..., 指标_切片n)
```

**为什么 mAP 替代不了**：单一聚合值会掩盖"在某个条件下彻底失效"。
一个在正午表现 95%、在清晨掉到 40% 的模型，均值可能仍有 70%——
但运维是在具体时刻飞无人机的，均值毫无意义。

**实测提示**：本项目在跨数据集测试中观测到极端不稳定
（同域图像级召回 97.44%，异域 0.10%），正是 CS 需要捕捉的现象。

---

### 6. LSR · 源图泄漏率（Leakage by Source Rate）

**定义**：训练集与验证集之间，同源原始影像（同一张源图的不同裁剪／增强）
重叠的比例。

```
LSR = 重叠源图数 / 验证集源图总数
```

**为什么必须报告**：它不是性能指标，而是**其他所有指标可信的前提**。
只要存在源图级泄漏，P/R/mAP 全部虚高，且虚高幅度不可估计。

**当前基线**：`LSR = 0`（已通过源图级审计清零，见项目数据集文档）

## 指标之间的关系

| 指标 | 回答的问题 | 谁最关心 |
|---|---|---|
| FAR | 会不会派冤枉工？ | 运维调度、成本控制 |
| wMR | 会不会漏掉要命的？ | 安全、资产管理 |
| LA | 找不找得到那块板？ | 现场施工 |
| ΔT-MAE | 有多严重、要不要现在处理？ | 检修决策、质保索赔 |
| CS | 换个条件还准吗？ | 排期、风险承诺 |
| LSR | 上面这些数能信吗？ | 所有人（前提） |

**FAR 与 wMR 是一对必须同时报告的权衡量。**
单独优化任何一个都可以作弊：阈值调到 0 可以让召回 100%，
调到 1 可以让 FAR 0%——两者都是无意义的。
**正确的呈现方式是 FAR–召回权衡曲线，并标出推荐工作点。**

---

## 基线实例：FAR–召回权衡曲线

PV-IRBench v0.1 实测（自有验证集 503 张，含负样本 151 张，权重 runs/final/best.pt）：

| conf | FAR | 每千块误报框 | 图像级召回 | StringFault 召回 |
|---|---|---|---|---|
| 0.25 | 0.00% | 0.0 | 93.47% | 56.2% |
| **0.10（推荐工作点）** | **0.00%** | **0.0** | **97.44%** | **84.4%** |
| 0.05 | 0.66% | 6.6 | 97.73% | 84.4% |
| 0.01 | 2.65% | 33.1 | 98.86% | 90.6% |

**读法**：在 conf=0.10 处，召回相对默认值提升 4 个百分点、
最弱类别提升 28.2 个百分点，而假警报率代价为零。
**这就是同时报告 FAR 与召回的价值——单看 mAP 永远发现不了这个工作点。**
