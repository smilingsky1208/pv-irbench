PV-IRBench

光伏红外缺陷检测的可信度评测基准

行业里所有人都在声称「准确率 95%」，但没有任何一把尺子能验证它。
PV-IRBench 就是那把尺子。

我们不训练最强的检测模型。我们做的是：定义一套能回答「这个模型能不能上工」的指标， 并把它开源出来，让任何人的声明都可以被复算。

三个真实存在的问题

一、mAP 不是运维要的指标

  • 它对负样本不敏感——一个在正常组件上疯狂误报的模型，mAP 依然可以很高。而误报意味着派人白跑一趟。
  • 它平等对待所有类别——漏检一个可能引发火灾的组串开路故障，和漏检一个轻微热斑，在 mAP 里损失相同。
  • 它不反映定位是否可用——框错到隔壁组件，IoU 仍可能达标，但报告作废。

二、各家的数字根本不可比

我们实测到：同一个模型，同域数据上图像级召回 97.44%， 在另一个公开数据集上只有 0.10%——相差近千倍。

尺度相差 16–26 倍。在这种情况下，任何「我们比他们高 5 个百分点」的说法都没有意义。

三、没人能测量假警报率

多数公开数据集与竞赛榜单不含足量纯负样本，因此 FAR 根本无法测量。 这就是「95% 准确率」永远无法被验证的原因。PV-IRBench 验证集负样本占比 30%（151/503）。

单看一个 mAP 数值，永远发现不了：把阈值从 0.25 降到 0.10，最弱类别召回提升 28.2 个百分点，而假警报率代价为零。

另一个发现：框级指标低估可用性

StringFault 的 mAP50-95 只有 0.407，看似很差；但在 conf=0.10 下图像级召回达 84.4%。 说明模型「知道这块板有问题」的能力，远强于「精确指出问题在哪」的能力—— 而运维筛查阶段只需要前者。

六个运维可用性指标

指标回答的问题
FAR 假警报率会不会派冤枉工？

使用

评测脚本与训练框架解耦——只要你的模型能对一批图片输出检测结果，就能算指标。

python benchmark/eval_far.py --source own \
  --data <数据集根>/solar_panel_v3_clean --split valid \
  --weights your_model.pt --conf 0.10

# 扫描多阈值，生成 FAR-召回权衡曲线
python benchmark/eval_far.py --source own --data <数据集根> --sweep

边界声明

为避免误用，明确以下边界：
· 同域结果不等于真实电站表现
· 图像级指标不代表定位精度
· 不主张跨数据集的横向对比
· 不具备 CMA/CNAS 资质，产出的是算法评测结果，不是具有法律效力的检测报告
