## 一、一个自报 mAP 78% 的模型，误报率 54%

我在 GitHub 上找到一个光伏红外缺陷检测模型：README 写着 mAP50 78%、8 类缺陷、MIT 许可可商用，权重直接放在仓库里。看起来是一个可以拿来就用的成熟方案。

我把它下载下来，用我们自己开源的评测协议跑了一遍。在 conf=0.10 这个常见阈值下：

| 指标 | 结果 |
|---|---|
| FAR（假警报率） | **54.30%** |
| 每千块正常组件的误报框 | **576.2** |
| 图像级召回 | 97.44% |

每两块正常组件，就有一块被它报成缺陷。

更值得注意的是：这个阈值不是我故意挑的。翻它的推理代码，作者硬编码了 `conf > 0.5` 的过滤条件，README 里只字未提。在他自己设定的阈值下，FAR 确实降到 0，但召回掉到 **87.22%**。

这不是要批评谁。它让我确认了一件更重要的事：**一个模型可以同时在指标表里表现优秀、在运维现场完全不可用，而这两个结论并不矛盾**。差别只在于你报告的是哪一个指标。

> 评测协议、指标定义与复算脚本已开源，本文所有数字都可复核：[PV-IRBench 项目主页](https://smilingsky1208.github.io/pv-irbench/) ｜ [代码仓库](https://github.com/smilingsky1208/pv-irbench)

## 二、为什么必须用同一把尺子

单个模型的数字没有意义，除非你知道它是在什么条件下测出来的。所以这一次我们把四个模型放在完全相同的条件下：

- **同一份验证集**：503 张，其中 151 张是纯负样本（完全正常的组件）——没有负样本，FAR 根本无从计算
- **同一批阈值**：conf 从 0.5 扫到 0.01，共 7 档，避免单一阈值下的偶然结论
- **同一套指标算法**：直接调用 `pv-irbench/benchmark/eval_far.py` 的 `compute_metrics()`，定义一个字未改
- **同一套真值**：固定使用数据集自身的 4 类标注，不用被测模型的类别名——四个模型类别体系不同，用各自的类别名做映射会污染结果

被测的四个模型：

| 模型 | 模态 | 许可 | 类别数 |
|---|---|---|---|
| 自研 YOLOv8（基准） | 红外 | 私有 | 4 |
| SolarPanelsDefectDetector | 红外灰度 | MIT（可商用，需署名） | 9（README 写 8） |
| SolarVulture | 红外 | **未声明** | 5 |
| Skytroll YOLO26 | 可见光 RGB | **未声明** | 5 |

两个指标的分工：**FAR** 衡量误报，即正常组件被误判为缺陷的比例；**图像级召回** 衡量检出，即有缺陷的图有没有被标出来。只报召回不报 FAR，等于只报收入不报成本。

## 三、结果：四款模型，七档阈值

下表格式：**FAR% / 图像级召回%**。

| conf | 自研 YOLOv8 | 开源 YOLOv9 | SolarVulture | Skytroll YOLO26 |
|---|---|---|---|---|
| 0.5 | 0.00% / 79.83% | 0.00% / 87.22% | 0.00% / 66.48% | 64.90% / 23.30% |
| 0.4 | 0.00% / 86.36% | 0.00% / 90.06% | 0.00% / 79.26% | 79.47% / 30.68% |
| 0.3 | 0.00% / 91.48% | 1.32% / 92.90% | 0.00% / 85.51% | 90.73% / 38.64% |
| 0.25 | 0.00% / 93.47% | 1.32% / 94.03% | 0.66% / 86.93% | 94.70% / 43.75% |
| 0.1 | **0.00% / 97.44%** | **54.30% / 97.44%** | 7.95% / 92.90% | 100.00% / 56.82% |
| 0.05 | 0.66% / 97.73% | 74.83% / 98.30% | 10.60% / 95.17% | 100.00% / 69.32% |
| 0.01 | 2.65% / 98.86% | 98.01% / 99.43% | 31.13% / 97.73% | 100.00% / 85.51% |

把视角收敛到"FAR=0 时的最高召回"——即不产生任何冤枉工单的前提下，哪个模型检出最多：

| 模型 | FAR=0 时最高召回 | 对应阈值 | 相对自研 |
|---|---|---|---|
| 自研 YOLOv8 | **97.44%** | 0.10 | 基准 |
| 开源 YOLOv9 | 90.06% | 0.40 | −7.38 pp |
| SolarVulture | 85.51% | 0.30 | −11.93 pp |
| Skytroll YOLO26 | 无 FAR=0 工作点 | — | — |

pp = 百分点。

### 发现一：mAP 与 FAR 之间，隔着一条工程鸿沟

开源 YOLOv9 在 conf=0.10 时召回 97.44%，和自研模型完全相同。但它的 FAR 是 54.30%。

把阈值提到 0.40，FAR 归零，召回降到 90.06%。这才是它能用的工作点。

它并非不能用——只是作者没有告诉你工作点在哪。README 上的 78% mAP 是一个与部署阈值无关的数字，而现场关心的是"在误报可接受的范围内，能检出多少"。

### 发现二：一个"差模型"，可能只是用错了地方

Skytroll 在全部七档阈值下，FAR 从 64.90% 一路升到 100%，没有任何零误报工作点。

如果只看这张表，结论是"这个模型很差"。但它是**可见光 RGB** 模型——训练数据里的缺陷是鸟粪、灰尘、物理损伤，而我们的验证集是红外热成像。把它放进红外图里测，本身就是模态错配。

这个案例恰好说明评测协议的价值：**它不只能给模型打分，还能诊断出"你用错了工具"**。对一个要采购巡检服务的业主来说，这个诊断比分数本身值钱——因为它避免的是把预算花在错误的技术路线上。

### 发现三：两个模型，许可状态是空的

SolarVulture 和 Skytroll 的 GitHub `license` 字段都是 null。法律上这意味着"保留所有权利"，而不是"免费可用"。

技术评测只回答"能不能用"，但一份完整的评估还得回答"能不能合法地用"。这一点被写进了报告的合规风险栏。

## 四、必须先声明的偏见

读到这里你可能会想：自研模型排第一，当然是你自己测出来的。

这个质疑是对的。我先把对自己不利的条件摆出来：

1. **自研模型是在这份验证集上同域训练的**。它见过同分布的图，天然占优。这不是公平盲测，是同域验证。
2. **三个开源模型的训练模态与验证集存在差异**。YOLOv9 用红外灰度、Skytroll 用可见光 RGB，而验证集是 RGB 伪彩红外。这些差异可能对它们不利。
3. **图像级召回不衡量框的定位精度**。一张图只要出现一个框就算命中，框得准不准不在本文指标范围内。

所以这份报告不能证明"自研模型更好"。它只能证明一件事：**FAR 这一维必须被报告，否则 mAP 再漂亮，也无法判断模型能不能落地。**

如果把同一把尺子反过来用在我自己身上——上一篇里我披露过自研模型的 mAP50 从 0.835 复算到 0.630——那么这一次我同样把它放进对比表，接受完全相同的条件。这才是"同一把尺子"的含义。

## 五、从"模型准不准"到"损失多少钱"

评测回答的是技术问题。但电站业主真正问的是另一个问题：**这些缺陷，值多少钱？**

所以在评测协议之上，我们还做了一条从图像到业务结论的交付管线：

1. **批量推理**：一个文件夹的航拍图进去，自动跳过坏图、多阈值推理，输出组件级结论。同一张图出现多类缺陷时只取最严重的一类，避免重复计算损失。
2. **损失量化**：按缺陷类别乘文献系数（热斑 1–3%、二极管 1–4%、旁路 3–8%、组串失效 30–100%），再乘组串年发电量与电价，给出保守 / 中性 / 乐观三档年损失。
3. **处置优先级**：按修复成本与回收期排 P0/P1/P2。例如演示参数下，组串失效换熔断器 300 元、回收期约 2 个月，属立即处理；热斑换组件 645 元、回收期 8.7 年，处置理由是安全风险而非电费。
4. **报告生成**：输出中文 PDF，含标注示例图、损失表、核查成本说明与边界免责声明。

在一次 150 张抽样的演示里，这套管线检出 104 块缺陷组件，年损失中性估计 43,853 元。其中 15 块组串失效贡献了 33,264 元——**不到 15% 的缺陷组件，贡献了 76% 的损失**。

这个数字的意义不在于精确，而在于它把"召回率 97%"翻译成了一个业主能据此做预算的东西。

> 注：该损失数字来自另一批 150 张抽样演示，与本文的 503 张模型复算是两个独立批次，不可直接换算。所有系数为公开文献取值与演示假设，实际项目需按电站参数重算。

### 附：本文边界

- 同域验证，不等于真实电站表现。所有模型均在同一份自建验证集上测试。
- 图像级口径，召回只回答"这张图有没有被标为异常"，不代表框级定位精度。
- 模态差异可能对外来模型不利，结论不外推为"模型本身差"。
- 两个开源模型许可状态未声明，商用前须取得作者书面授权。
- 本次评测为算法评测结果，不具备 CMA/CNAS 资质，不作为法定检测报告。
